# Artefactos técnicos — SaaS Educativo Angola

Versão inicial: 0.1.0  
Stack: Laravel API + PostgreSQL + React + TypeScript  
Âmbito: escolas (ensino primário e I ciclo) e centros de formação.

## Conteúdo

- `docs/modelo-dados.md`: modelo relacional, decisões, índices, isolamento multi-tenant e regras.
- `database/schema.sql`: esquema PostgreSQL de referência para revisão técnica.
- `api/openapi.yaml`: contrato REST inicial em OpenAPI 3.1 para consumo pelo frontend React.
- `laravel/database/migrations/`: migration inicial para as tabelas nucleares de plataforma e identidade.
- `docs/plano-implementacao.md`: sequência recomendada de implementação e critérios de validação.

## Antes de usar em produção

Estes ficheiros são uma base de engenharia inicial, não uma versão certificada para produção. Rever especialmente:
1. requisitos legais e fiscais aplicáveis em Angola;
2. política de retenção/eliminação de dados pessoais de menores;
3. regras exactas de matrículas, pagamentos, recibos e certificados;
4. modelo de autenticação e configuração de cookies/CORS/CSRF;
5. política de subscrição e de suspensão;
6. requisitos de auditoria e backup.

O SQL usa `BIGINT GENERATED BY DEFAULT AS IDENTITY`. Em Laravel, os modelos podem usar `$table`, `$fillable`/casts e policies conforme a organização do projecto. A coluna `institution_id` representa o tenant. Em tabelas com dados institucionais, a aplicação deve obter o tenant do contexto autenticado, não confiar cegamente no valor enviado pelo frontend.

## Como validar o SQL

Num ambiente de desenvolvimento PostgreSQL vazio:
```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f database/schema.sql
```

O SQL é uma referência de esquema; se as migrations Laravel forem a fonte de verdade, mantenha o SQL sincronizado com elas. Não mantenha dois mecanismos independentes de evolução do esquema.

## Convenções

- Datas de negócio: `DATE`; instantes: `TIMESTAMPTZ`.
- Valores monetários: `NUMERIC(19,2)` (não usar float/double).
- Identificadores públicos de recibos/certificados: códigos não sequenciais e não adivinháveis, além da PK interna.
- Estados: `VARCHAR` com `CHECK` no MVP; considerar enums/tabelas de referência quando houver necessidade real.
- Exclusão: preferir estados de cancelamento/arquivamento e histórico a apagar registos financeiros ou académicos.
